# SortMySkills Big Flow Refactor Prompt

You are working inside the existing SortMySkills Next.js app.

This is a large product-flow improvement, not a rebuild.

The goal is to make the app feel more intuitive, cleaner, and more powerful without breaking authentication or any existing functionality.

The app needs a better opening dashboard, and Job Match, ATS Scorer, and Career Roadmap need to be merged into one intuitive analysis workspace. This workspace should not feel like separate tabs. It should feel like one guided flow where the user pastes their resume and job description once, then chooses different actions from the same place.

Why No Reply must remain separate because it is the MVP.

Skill Parser must be removed as a user-facing feature.

Do not include new unnecessary features. Consolidate what already exists and make the product flow better.

---

## Absolute Safety Rules

Do not break, modify, simplify, or remove authentication.

Do not touch or alter behavior for login, signup, forgot password, reset password, OTP or email verification, Supabase session handling, auth helpers, auth middleware, protected routes, profile sync, email or auth environment variables, existing auth redirects, or existing auth layouts.

Authentication must work exactly as it currently works after this change.

Also do not break the dashboard layout shell, global app layout, theme system, GSAP or Lenis animations, Supabase integration, ResumeContext or localStorage behavior, Profile page, Resume Builder, Interview Packs, Why No Reply, the roadmap API, email-related logic, or existing UI components.

Make the smallest safe changes required for the new product flow.

---

## Current Problem

The app currently feels fragmented because the core career-analysis features are split into separate pages.

The current separate tools are Job Match, ATS Scorer, Career Roadmap, Skill Parser, and JD Translator.

This makes users think they need to choose the correct tool manually.

The product should instead guide users through one intuitive flow.

The app should open with a better Overview dashboard, then naturally guide users into one merged analysis workspace.

---

## Final Product Direction

The app should feel like this.

First, the user lands on a strong Overview dashboard.

Second, the Overview clearly tells them what to do next.

Third, the user opens one merged analysis workspace.

Fourth, that workspace accepts resume text and target job description text once.

Fifth, from there, the user can run ATS scan, Job Match, and Career Roadmap using separate action buttons.

Sixth, results appear progressively in one flowing page.

Seventh, Why No Reply stays separate as the MVP emotional diagnosis.
